# Сергей — кабинет собственника

[Открыть демонстрацию](https://esvdox.github.io/sergey-owner-finance/) · [Визуальный стандарт](https://esvdox.github.io/sergey-owner-finance/style-guide.html) · [ТЗ для команды](docs/SPEC.md) · [Приёмка](docs/ACCEPTANCE.md)

Отдельный финансовый dashboard в мягком объёмном стиле предоставленного референса. Существующий AVERA не изменяется. Русский интерфейс, крупный текст, четыре управленческих вопроса, графики и раскрытие до отчёта.

## Запуск

Node.js 20+; внешних npm-зависимостей нет.

```sh
npm start
```

Открыть http://127.0.0.1:4173 . По умолчанию показан явно обозначенный учебный пример. `npm test` проверяет финансовые инварианты. `public/style-guide.html` — библиотека компонентов. Полное ТЗ: [docs/SPEC.md](docs/SPEC.md).

Для браузерной проверки нужен Playwright с Chromium: установить его в тестовое окружение и выполнить `node scripts/browser-check.cjs`. Можно передать расположение пакета через `PLAYWRIGHT_PATH`; переменная `CHECK_URL` задаёт адрес проверяемого стенда. Без неё тестируется локальный порт4173. Сам сайт не зависит от Playwright.

Для публикации после тестов: `git subtree split --prefix public` создаёт commit статической части; отправить этот commit в ветку `gh-pages`. В настройках Pages выбрана эта ветка и корень. Не отправлять runtime. CI проверяет `main`, GitHub Pages автоматически публикует изменения `gh-pages`.

## Рабочие данные и автоматическое обновление

Установить `DASHBOARD_USER` и `DASHBOARD_PASSWORD` в окружении процесса, не в Git и не в frontend. Опционально задать `DATA_DIR` для внешнего закрытого хранилища и `PORT`. По умолчанию сервер слушает только127.0.0.1. Рабочее размещение — за TLS и корпоративной авторизацией; Basic используется только на стенде/в защищённом контуре.

Положить нормализованный JSON по контракту `public/model.mjs` в `runtime/inbox/`. Файл должен иметь `isDemo:false`; это допустимо только для реального проверенного снимка, не для переименования учебных чисел. Поставщик пишет сначала временный файл, затем атомарно переименовывает в `.json`. Сервер проверяет папку каждые15сек, сверяет формы, сохраняет архив и атомарно обновляет current. Ошибочный файл переносится в rejected с причиной; последний принятый снимок сохраняется. Интерфейс «Мои данные» читает `/api/snapshot` каждую минуту, когда вкладка видима. Для локального просмотра можно импортировать JSON в браузер; он никуда не отправляется.

Адаптеры 1С/банков/CRM/производства описаны в ТЗ, но пока не подключены. Прямого импорта произвольной ОСВ Excel нет: сначала требуется маппинг счетов и аналитики. Пример содержит все поля схемы, но не настоящие первичные документы. Предварительные данные обозначаются явно.

## GitHub

Публично размещаются только frontend и синтетический набор. GitHub Pages обслуживает `public` через отдельную ветку публикации; рабочий сервер там не запускается. Нельзя класть реальные снимки в публичную ветку или артефакты Actions. `.gitignore` исключает runtime, .env, локальные артефакты и частный референс. CI запускает финансовые тесты при push/PR.

## Дизайн

CSS воспроизводит палитру, встречные тени, объёмные кнопки и утопленные поля изображения. Микротекст увеличен для возрастных пользователей. Исходные CSS/JS и шрифт референса неизвестны; точное совпадение с фотографией не заявляется. Измерения и отклонения задокументированы. Для внешней команды эталон реализации — поставляемые CSS, HTML, данные и контрольные снимки.
